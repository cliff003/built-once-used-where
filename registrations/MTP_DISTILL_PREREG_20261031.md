## 1. 读数的定义
- **位置**：H10 留出游戏的生成 token，与 T0 同一批位置；reasoning 权重 2；去重规则同 T0。
  - **[F 加]** 算第一个 AL 之前，先冻结位置清单的 sha 和位置数。AL_base、AL_new 和 T0 都用这同一份清单。
- **链**：NEXTN 3 步，eagle-topk 1。
  - 每一步草稿提议自己的 argmax；递归时用草稿自己的隐状态和上一步提议的 token。
  - 第 k 步的提议与日志 token 不同，链就在那里停。
- **单位**：生成 token ÷ verify 步，含验证后多出的那 1 个 token，与 SGLang 的 accept_len 同一记法，取值在 [1, 4]。
- **[F 加] 主读数是 AL_mc**：沿 teacher forcing 的日志序列，“日志 token == 草稿 argmax”记为接受，与 T0_mc 同一种。
  - 日志 token 是处理后 p 的样本，所以每一步被接受的概率就是 p(d)，正是 target-only 验证的接受概率。链上一旦接受，上下文就与日志一致，所以整条链的抽样也无偏。
  - **AL_exp 只作一致性核对**：每步按处理后的 p(d) 做伯努利，64 次固定种子重放，采样设定同 T0。它在接受了 d ≠ 日志 token 之后，用的还是日志的上下文，是近似值。
- **[F 加] 采样设定**：处理顺序同 SGLang，即温度、top-k 20、top-p 0.95。
  - 温度必须与 T0 的 C1 选出的 T 一致，也要与 S9 notebook（`39fc6f22`）里实际的采样设定一致。
  - 三者不一致就判 UNDETERMINED、停：那样的 AL_mc 量的不是部署时的接受率。
  - 训练时 KL 的目标分布也用这同一组设定。
